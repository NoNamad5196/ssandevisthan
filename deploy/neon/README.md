# Neon Free backend

The user authorized replacing Supabase because both existing Free projects must stay active. PostgreSQL DTOs, owner isolation, ranking, budgets and durable jobs are retained. The API runs on Neon Node24, with a private `search-images` S3 bucket and custom rotating anonymous sessions. Managed Auth, Data API and AI Gateway are disabled.

Build with `node deploy/neon/build.mjs`. The observed Singapore runtime is Linux ARM64/glibc. The build verifies the native ELF architecture and excludes other architectures/WASM to satisfy the platform's 10MiB compressed archive limit. Bundled native dependency licenses remain present. Run `npm run typecheck --workspace @ssandevisthan/api` and the tests before deploying.

Apply the initial schema with `DATABASE_URL` injected into `node deploy/neon/migrate.mjs`. Checksummed migrations are transactional and cannot be silently rewritten after application. Use a new migration for later changes. The bootstrap is only for this dedicated project; it must not run against an existing unrelated database.

`node deploy/neon/deploy.mjs deploy` uses project-scoped credentials from the environment or ignored `.secrets/neon.json`, and deployment settings from ignored `.secrets/backend.env.json`. It does not print secrets. The first actual function URL is saved to the settings; redeploy once so JWT issuer and worker URLs use that real origin. `configure` also performs a full deployment because an observed config-only REST request returned400. `trigger` creates or updates only this project's `search-sweep` schedule. The equivalent declarative configuration is `deploy/neon/neon.ts`.

The platform injects database/S3 credentials. Server-only settings are listed in `.env.example`. The public frontend needs only `VITE_API_BASE_URL=<actual HTTPS origin>`; the client appends `/functions/v1/api/v3`. No server key is public. Anonymous POST/refresh use schemaVersion3 and return accessToken, refreshToken, UTC expiresAt, userId in the normal API envelope. Access tokens last1h; refresh tokens30d, rotate, and tolerate15s response-loss replay without changing owner.

The GitHub backend workflow runs only for a successful verification of the current main commit. It uses the pinned Neon CLI and encrypted `NEON_API_KEY`, `NEON_DATABASE_URL`, and `NEON_BACKEND_ENV_JSON` repository secrets. The JSON secret contains the stable existing server settings, including JWT/worker/schedule secrets and the paid-execution flag; CI never creates replacement keys. Current-main and successful-verification checks run again immediately before migration/deployment. Dependency artifacts, frontend bundles and logs contain no server secrets.

Every-minute scheduler calls require the independent private path marker and Neon’s stripped/attested trigger header. A forged trigger header was rejected404 on the live platform. PostgreSQL minute deduplication prevents duplicate active sweeps. Private S3 activity markers are written before admission; idle calls avoid waking Postgres, and durable future markers wake it at the next retention deadline. This prevents a permanently warm0.25CU database solely because a minute cron exists. Free quota is finite under real traffic; do not enable billing automatically.

Image admissions cap unexpired uploads at10 per owner/100 globally and2 concurrent decoder leases; each raw input remains bounded10,000,000bytes/24MP. Only normalized copies are stored. Object writes are conditional and never overwrite different normalized bytes. Cleanup tasks and a paginated orphan scan handle interruption/deletion races. The object scan records hard-TTL violations. Images expire within1h and terminal cleanup is scheduled at4min; API visibility checks expiry independently. Search snapshots expire after7days. Scheduler/cleanup delay is reported rather than hidden.

The internal-secret diagnostics endpoints test a synthetic24MP image in RAM and public pinned HTTPS/SSRF blocking. They contain no user input and never log image bytes. Their live results are in `docs/deployment/`. Only set NORMALIZER_VERIFIED/EGRESS_VERIFIED after those checks pass. `smoke.mjs` tests two real owners, upload/finalize, private storage, refresh, deletion and physical cleanup; it explicitly reports zero provider calls.

Paid execution remains disabled until historical cumulative pilot spend, the exact model, official rates, input/output/tool reservation caps and free service quotas are verified in `pilot_budget`. The USD20 pilot cap does not reset by date. The OpenAI key is server-only. Unknown external charge outcomes retain reservations; no automatic refund or model substitution occurs. A working upload is not a LIVE product-search success.

Migration005 leaves `minimum_search_reservation_microusd` NULL, deliberately blocking new paid runs until configuration is verified. Configure it atomically with `rates` and `rates_verified_at` as the maximum of `quoteCost(rates, operation)` for analysis, discovery and comparison. The configured per-search ceiling must cover this floor and cannot expand the global USD20 cap. Admission reserves the smaller of the per-search ceiling and cumulative remaining unreserved balance. One discovery call is committed per checkpoint; known usage replaces its conservative reservation before the next call. Unknown usage stays reserved, including after cancellation. Insufficient next-call headroom stops discovery and ranks only already verified candidates.

`node deploy/neon/configure-budget.mjs` previews the exact rate snapshot and shared cost-calculator output with no network or database write. The 2026-10-09 Standard/global snapshot uses output caps4000/1000/8000; its largest operation reservation is USD10.525. After the operator provides the actual cumulative historical total, `node deploy/neon/configure-budget.mjs --historical-total-usd <confirmed-total> --apply` records that total and verified rate/model configuration in one locked transaction. Inject `DATABASE_URL` and `OPENAI_API_KEY` only in the server environment. It refuses enabled execution, previous history verification, a decreased recorded total and a stale rate snapshot. It preserves all reservations, the global cap and the quota flag; it never enables paid execution or deploys the key. The supplied total must include already recorded settled pilot costs, with unresolved reservations kept separately. Do not use an example amount as historical evidence.

Activation is a separate operation after historical reconciliation and actual Free capacity checks: verify `free_quota_verified_at`, deploy the server-only OpenAI key, and then intentionally enable both the database budget and `PAID_EXECUTION_ENABLED`, preserving stable JWT/worker settings and encrypted CI settings. Run one real bounded search and inspect actual provider usage/settlement before expanding validation. Missing usage keeps reservations held. Until those checks are satisfied, preserve the current disabled deployment.
